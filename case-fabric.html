03MICROSOFT FABRIC · RETAIL

Unified Retail Analytics Lakehouse

An end-to-end Fabric platform integrating orders, returns and inventory into a single Delta-based retail model, ready for analytical consumption through Direct Lake.

ROLEData Engineer
PLATFORMMicrosoft Fabric · OneLake
PATTERNUnified domain model
CONTEXTEpsilon · 2022–2025

THE PROBLEM

Three datasets that described the same business.

Orders, returns and inventory arrived as separate extracts with their own field names, date formats and product identifiers. Any question that crossed them — return rate by product, stock against demand — required manual reconciliation before it could be answered at all.

Because each dataset was analysed independently, the same metric could be produced three different ways and disagree with itself, which is the fastest way for a reporting layer to lose credibility.

ARCHITECTURE

How it fits together.

ENGINEERING DECISIONS

What was chosen, and why.

Conform before integrating

Null handling, duplicate removal and datatype conversion run before the datasets are joined, so integration operates on predictable inputs rather than absorbing source inconsistency.

→ Joins stop producing surprises.

One vocabulary across domains

Product identifiers, date grains and status fields were standardised to shared business definitions, so the same column name means the same thing in all three datasets.

→ Cross-domain questions become answerable.

Delta tables in OneLake

The unified model is written as Delta rather than as extracts, giving ACID guarantees and time travel inside Fabric's single storage layer.

→ One copy serves every workload.

Direct Lake as the serving path

The model is shaped for Direct Lake consumption, so reporting reads Delta files directly instead of maintaining a separate import copy.

→ No duplicated serving dataset.
